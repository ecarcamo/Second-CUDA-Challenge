¿8,3× o 7,3×?

La GPU no decodifica: en las dos versiones lo hace la CPU. Lo que cambia es cuántos hilos de CPU quedan libres para hacerlo.

Medido · cada versión en su mejor configuración

8,3×
S = TCPU / TGPU
  = 1 445,8 s / 173,3 s
  = 8,3×

CPU: la red usa los núcleos y decodifica con 8 hilos, 53,5 s. GPU: la red se va a la tarjeta y la CPU decodifica con 32 hilos, 27,6 s.

Teórico · Ley de Amdahl

7,1×
s = (19,1 + 53,5) / 1 445,8 = 0,050
k = 1 293,7 / 122,8 = 10,5
S = 1 / (s + (1 − s) / k)
  = 1 / (0,050 + 0,950 / 10,5)
  = 1 / 0,140 = 7,1×

s: lectura y decodificación, lo que no acelera la GPU. k: cuánto se acelera la inferencia. Supone que la parte de CPU no cambia.

Medido · los mismos 8 hilos en las dos

7,3×
S = TCPU / TGPU, 8 hilos
  = 1 445,8 s / 198,4 s
  = 7,3×

Decodificar vuelve a tardar 53,6 s, igual que en la CPU. Lo medido coincide con Amdahl.

Con 32 hilos, la versión GPU tarda 25 s menos (198,4 s → 173,3 s). Esos 25 s los gana la CPU al quedar libre de la red, no la GPU.

El kernel, línea por línea

Resumido de gpu/preprocess.py · 14 × 14 × 64 bloques de 16 × 16 hilos = 3,2 millones de hilos por lote

template <typename T>
__global__ void crop_area_normalize(const T* src, float* dst,
const int* starts, const int* ends, int width, int out,
float scale, float shift)
{
int x = blockIdx.x * blockDim.x + threadIdx.x;
int y = blockIdx.y * blockDim.y + threadIdx.y;
if (x >= out || y >= out) return;
const T* img = src + blockIdx.z * width * width;
int r0 = starts[y], r1 = ends[y];
int c0 = starts[x], c1 = ends[x];
float sum = 0.0f;
for (int r = r0; r < r1; ++r)
for (int c = c0; c < c1; ++c)
sum += (float)img[r * width + c];
float mean = sum / ((r1 - r0) * (c1 - c0));
dst[(blockIdx.z * out + y) * out + x] =
__fadd_rn(__fmul_rn(mean, scale), shift);
}
  1. Una plantilla para dos tipos. El mismo kernel lee uint8 o float32. __global__: corre en la GPU y lo lanza la CPU.
  2. ¿Qué píxel soy? Cada hilo saca su columna y su fila de salida con su bloque y su posición dentro del bloque.
  3. ¿Qué placa? El eje z de la cuadrícula elige una de las 64 placas del lote.
  4. ¿Dónde está mi caja? Dos tablas calculadas una vez en la CPU dicen dónde empieza y termina: 5 o 6 píxeles por lado.
  5. Sumar. Lee de 25 a 36 enteros de 1 byte y los pasa a float aquí, no antes de copiar.
  6. Promediar, normalizar y escribir. media × 2048/255 − 1024, sin FMA para dar lo mismo que NumPy. Una escritura por hilo.

Fracción secuencial y paralelizable

Secuencial es lo que la GPU no acelera: leer y decodificar se quedan en la CPU en las dos versiones. Se mide sobre TCPU porque Amdahl parte del programa original.

Etapa en la versión CPUTiempo%Parte

Puntaje y orden0,1 s0,0paralelizable
TCPU1 445,8 s100
s = (lectura + decodificación) / TCPU
  = (19,1 + 53,5) / 1 445,8 = 72,6 / 1 445,8
  = 0,0502 → 5,0 %
p = 1 − s = 0,9498 → 95,0 %

Techo: 1 / s = 1 / 0,0502 = 19,9×
k = inferencia CPU / GPU = 1 293,7 / 122,8 = 10,5
Predicción: S = 1 / (s + p / k)
  = 1 / (0,0502 + 0,9498 / 10,5)
  = 1 / 0,1407 = 7,1× · medido con 8 hilos: 7,3×

En la versión GPU las mismas etapas secuenciales pesan 26,6 % de TGPU: no se volvieron lentas, el resto se encogió. Las etapas suman 0,2 s menos que el total; esa diferencia queda dentro de p.
